# Telegram-бот-конструктор — v1.1.15 (Python без Docker)

## Изменения v1.1.15

- Создание заявки на лицензию атомарно защищено от одновременных callback-запросов. Тариф и способ оплаты перепроверяются перед записью.

## Архитектура: два типа ботов

1. **Бот-конструктор** принимает токен от `@BotFather`, проверяет его через Telegram API и управляет подключёнными ботами.
2. **Персональный бот подписок** запускается отдельным процессом Python на токене клиента и имеет собственную SQLite-базу. Владелец настраивает тарифы, каналы, способы оплаты, заявки, подписки, лицензии и рассылки в административном меню персонального бота.

Третий бот не нужен. Конструктор и каждый подключённый бот запускаются отдельными Python-процессами. Docker не используется.

## Запуск на Windows

1. Установи Python 3.11 или 3.12 с опцией **Add Python to PATH**.
2. Распакуй архив в отдельную папку, например `C:\bot-constructor`.
3. Открой PowerShell в этой папке.
4. Создай виртуальное окружение и установи зависимости:

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
```

5. Создай `.env` и открой его для редактирования:

```powershell
Copy-Item .env.example .env
notepad .env
```

6. Впиши `CONSTRUCTOR_BOT_TOKEN` и свой числовой Telegram ID в `OWNER_IDS`. Сохрани файл.
7. Запусти конструктор:

```powershell
python main.py
```

Чтобы остановить конструктор, нажми `Ctrl+C`. Для повторного запуска используй ту же команду из папки проекта.

## Подключение персонального бота

1. Создай тестового бота через `@BotFather`.
2. В конструкторе нажми «➕ Создать бота» и отправь токен. Сообщение с токеном удаляется по возможности.
3. Открой подключённого бота кнопкой в «🤖 Мои боты» и отправь ему `/start`.
4. Настрой тарифы, каналы, способы оплаты и другие функции через его административное меню.
5. Добавь бота администратором в необходимые каналы и выдай права, нужные для создания приглашений и управления подписчиками.

## Файлы и логи

- `data/constructor.sqlite3` — база конструктора.
- `instances/clientbot_<owner>_<botid>/.env` — настройки и токен конкретного бота.
- `instances/clientbot_<owner>_<botid>/data/subscriptions.sqlite3` — отдельная база подписчиков.
- `instances/clientbot_<owner>_<botid>/bot.log` — лог конкретного персонального бота.
- `instances/clientbot_<owner>_<botid>/bot.pid` — PID-файл запущенного процесса.

Не публикуй `.env` и каталог `instances`: они содержат токены и данные пользователей. Токен даёт полный контроль над ботом. Если токен раскрыт, отзови его через `@BotFather`.

## Важные замечания

- Конструктор и персональные боты должны работать на машине с постоянным интернет-соединением.
- Персональные боты запускаются отдельными процессами Python, а не Docker-контейнерами. Кнопки запуска, остановки, перезапуска и удаления управляют этими процессами.
- Для Windows требуется пакет `psutil`, установленный автоматически через `requirements.txt`, чтобы управлять процессами после их отделения от конструктора.
- Это не Windows-служба: при перезагрузке компьютера персональные процессы автоматически не восстанавливаются. Запусти `python main.py` снова и проверь статусы; если потребуется автозапуск при старте системы, его нужно настроить отдельно.
- Проверка синтаксиса и архива не заменяет интеграционную проверку с настоящим Telegram API. Сначала проверь на тестовых ботах.

## Изменения v1.1.11
